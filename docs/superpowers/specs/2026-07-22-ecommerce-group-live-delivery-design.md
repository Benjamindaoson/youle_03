# 电商专业群真实交付设计

## 目标

把现有 `ecommerce_detail_image` Skill 从本地 mock 演示收敛为一个真实交付的专业群聊能力。用户只在群里上传商品图、说明卖点和确认图片数量；系统不新增独立电商页面、第二套工作流或第二个编排器。

## 群成员

电商专业群只包含：老板、总裁助理、研究员/文案师（Agent 1）、设计师（Agent 3）和文档专员（Agent 2）。

- 总裁助理：识别电商详情图需求、收集缺失输入、展示生成计划和成本预估、请求确认、编排交付。
- Agent 1：生成商品卖点、标题和分段详情文案。
- Agent 3：分析商品图，按用户确认的数量生成、重绘和质检分段图。
- Agent 2：仅在已确认的图片完成后拼接详情长图，不调用模型。

影音师不在电商图文群内；HR 与财务经理只留在主会话。

## 模型与成本纪律

- 文本、意图和文案默认使用 DeepSeek。
- 图像默认使用字节火山方舟 Seedream。
- 长图拼接使用本地 Pillow。
- 不自动切换到海外模型，也不在模型失败时进行隐式重试或替代调用；总裁助理在群里报告失败并等待用户决定。
- 每次图片模型调用都必须先由用户在群里确认图片数量。首图、补图、单张重绘和批量重绘全部适用；系统仅展示预估成本，不能自动消费。

## 群聊交互

1. 用户在群里发送商品图和目标。
2. 总裁助理补齐卖点、受众、风格等必要字段；文本工作可在低成本模型上完成。
3. 总裁助理列出本次要生成的图片数量、用途和预估成本，并给出可点击选项。
4. 用户确认准确数量后，才创建对应的图像任务。
5. 设计师回传图片；需要补图或重绘时，重复第 3–4 步。
6. 文档专员拼接已确认的图片，群聊中交付长图、文案和分段图。

## 非目标

- 不新增独立电商后台、向导页面或并行编排框架。
- 不在首期加入视频、投放、上架、商品发布或海外模型兜底。
- 不允许系统自行决定图片数量或绕过确认批量生成。

## 验收

- 普通群可被配置为电商专业群，成员列表不含影音师、HR、财务经理。
- 每次真实图片调用前都存在持久化的用户确认；未确认时 Redis/模型端均不会收到图像任务。
- 已确认数量等于实际请求的图片数量；重绘视为新的确认。
- 使用 DeepSeek、Seedream 和本地拼接完成一次可下载的电商详情长图交付。
- 模型或图片生成失败时，群聊显示失败状态，不触发未获确认的重试或海外模型切换。
