# `agents/` — 主编排 + 四个专职 Agent

本目录是 Python 包 `agents` 的实现根目录,承载本系统的多 Agent 架构:
**1 个主编排 Agent(在 backend 进程内运行)** + **4 个专职 Agent(独立 worker 进程)**,
共享协议与工具集中在 `_common/`。

> **角色与代码的命名差异**:产品语境里主编排被称作「总裁助理」,
> 代码里它的入口在 `agents.orchestrator_agent`(如 `runner_factory`、`langgraph_runner`)。
> 文档/UI 文案用产品语,代码/日志/队列用工程语,二者不混用。

---

## 角色对照表

| 工程目录 | import 路径 | 角色 | 队列 agent_id | 队列 channel |
|---------|------------|------|--------------|-------------|
| `orchestrator_agent/` | `agents.orchestrator_agent` | 主编排(Skill 匹配 / Brief 解析 / LangGraph 执行 / HITL / Redis 派发) | — *(不占 worker 槽)* | — |
| `text_agent/` | `agents.text_agent` | 文字 Agent | `agent_1` | `agent_tasks:text` |
| `document_agent/` | `agents.document_agent` | 文档 Agent | `agent_2` | `agent_tasks:document` |
| `image_agent/` | `agents.image_agent` | 图像 Agent | `agent_3` | `agent_tasks:image` |
| `av_agent/` | `agents.av_agent` | 影音 Agent | `agent_4` | `agent_tasks:av` |
| `_common/` | `agents._common` | 共享层 | — | — |

### 命名约定(写代码前先看)

- **目录名 = 角色英文 + `_agent` 后缀**(`text_agent`、`image_agent` …),不要写成 `agent_text/` 或 `text/`。
- **agent_id = `agent_{N}`**,N 是 1–4 的固定编号,**与目录名解耦**。
  - 重要:`agent_3` 这个 id 在 Redis 队列、日志、监控、计费分摊里都是稳定 key,**不要随业务改名**。
  - handler / 入口里如果出现 `"agent_3"` 字面量,提取为模块顶部 `AGENT_ID` 常量,只声明一次。
- **队列 channel = `agent_tasks:{kind}`**,kind 是业务类别(text/document/image/av),不是编号。
  - 这层抽象让"未来某个 agent_id 重组到其他 channel"成为可能,所以业务代码引用 channel 而非 id。

## 主编排 vs 专职 Agent 的部署边界

| 维度 | 主编排 | 专职 Agent |
|------|-------|-----------|
| 运行位置 | backend 进程内(asyncio task / LangGraph runner) | 独立 worker 进程,K8s 部署 |
| 触发方式 | HTTP / WebSocket 事件 | 消费 Redis Stream 队列 |
| 依赖 | LangGraph、Redis(派发)、HITL 中断 | LiteLLM、OSS、Temporal(长任务) |
| 失败语义 | session 级回滚 / 用户可见错误 | task 级重试 / 死信队列 |

**这条边界是设计铁律**:专职 Agent 不直接调 LangGraph,主编排不直接调模型 API。
跨边界的所有交互都走 `AgentTask` / `AgentResult` 协议(见 `_common/protocol.py`)。

---

## `_common/` 职责边界

`_common/` 只放**所有 4 个专职 Agent 都会用到**的东西:

- **协议层**:`protocol.py`(`AgentTask` / `AgentResult` / `ArtifactRef`)
- **运行时**:`consumer.py`(Redis 消费 + handler 调度 + ReAct 兜底)
- **基础设施**:`llm.py`(LiteLLM 封装)、`oss_writer.py`、`flywheel_emitter.py`
- **路由 / 人格**:`react_personas.py`

不放进去的:
- 单个 Agent 才用的业务逻辑(放各自目录)
- backend 通用工具(放 `backend/app/...`)
- 跨多服务的领域模型(放 `backend/app/domain/`)

判断标准:**4 个 Agent 都 import 才是 `_common/`,3 个 Agent import 就放被复用方自己的目录然后被显式 import**。

## 我该改哪里?

| 你想做的事 | 改这里 |
|----------|-------|
| 加一个新的 Skill(比如「视频号脚本」) | `orchestrator_agent/`(注册 Skill) + 对应 `*_agent/handlers/`(实现 task) |
| 给某个 Agent 加新 task 类型 | `{agent}/handlers/{task_name}.py` + 对应 `main.py` 注册 |
| 改 LLM 路由策略 | `_common/llm.py` 或 `{agent}/handlers/` 里的路由文件(如 `image_agent/handlers/xhs_model_router.py`) |
| 改 task 协议字段 | `_common/protocol.py` + **同步检查 4 个 Agent 的 handler** |
| 改 ReAct 人格 | `_common/react_personas.py` |
| 改主编排的 LangGraph 流程 | `orchestrator_agent/langgraph_runner.py` 等 |
